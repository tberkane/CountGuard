# CountGuard

**Audit and protect aggregate patient-count releases against reconstruction attacks.**

Federated research networks such as Cumulus answer queries with tables of patient counts over
every combination of a few variables (*count cubes*). Small counts are suppressed, for example
everything below 10, to protect patients. But the published counts constrain the suppressed ones,
and integer programming can often recover them exactly.

CountGuard is an Apache-2.0 Python library and command-line tool that

1. **attacks a release**: proven [min, max] bounds on every suppressed count under two attacker
   models, plus the Bayesian reconstruction of the original research code;
2. **protects a release**: suppression (rows omitted or shown as "1-9"), rounding, generalization,
   and differential privacy via [OpenDP](https://opendp.org), composable as
   generalize → DP → suppress/round;
3. **measures the tradeoff**: re-identification risk against accuracy loss across settings, with the
   Pareto frontier and the setting closest to a target.

!!! note "Synthetic data only"
    CountGuard v0.1.0 is an early release. Every number in this documentation comes from
    **synthetic** cohorts generated by `countguard.synth` (a kidney-transplant-like cohort,
    seed 2, with n = 285 or n = 20,000 patients). No patient data is used.

## Background

CountGuard builds on the research code of the medRxiv preprint *Sharing aggregated patient counts
in place of line-level EHR data: analytic fidelity and the limits of count suppression for privacy*
(Chen, McMurry, Gottlieb, Jones, Strober, Mandl; 2026;
[doi:10.64898/2026.08.18.26359984](https://doi.org/10.64898/2026.08.18.26359984)). That code
is included unmodified in the repository's `reproduction/original/` (Apache-2.0).
